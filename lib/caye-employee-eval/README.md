# Caye Employee Eval

`caye-employee-eval/1.0.0` is a frozen, state-first benchmark for whether Caye is becoming an excellent small-business employee.

It is intentionally separate from `lib/caye-bench`. The existing Caye Bench and replay corpus remain unchanged and continue to test their existing safety/execution contracts. Employee Eval adds a second layer focused on business learning, memory, opportunity detection, economics, autonomous work, interruption quality, isolation, time, recovery, and observability.

## Rule of evidence

A good conversational answer is not enough. Employee Eval scores durable facts, retrieval observations, opportunity rows, action outcomes, evidence/provenance, and an economic outcome ledger. The adapter seam in `runner.ts` receives frozen events and returns an observable snapshot. The evaluator never requires a particular internal helper or database implementation.

Learning traces explicitly cover:

`OBSERVE → EXTRACT → CLASSIFY → RESOLVE → STORE → RETRIEVE → ACT → CORRECT`

A required trace that cannot be evaluated is a hard failure. Missing coverage is not interpreted as success.

## Frozen scenarios

- `ods-construction-end-to-end-v1`: authoritative onboarding from an empty memory store, service and estimate inquiries, vendor invoice, unsigned PandaDoc proposal, repeated project-status requests, and an owner correction to quote policy.
- `bimini-island-tours-end-to-end-v1`: tour pricing/minimums, stale pickup memory, owner correction to Casino Tram Stop, fresh retrieval, payment-ready customer with a missing workflow, stale inquiry, repeated opportunity scans, founder job-search contamination probe, and engineering/FEA contamination probe.

The event streams live in `scenario-events.ts`; expectations live in `fixtures.ts`. Changing either requires a new benchmark version. Do not edit v1 expectations merely because production performs poorly.

## Dimensions

The report scores these independently from 0 to 10:

1. onboarding learning
2. continuous learning
3. memory correctness
4. contradiction handling
5. provenance/authority
6. retrieval quality
7. proactive opportunity detection
8. economic relevance
9. autonomous execution
10. human interruption quality
11. task completion
12. workspace/context isolation
13. temporal reasoning
14. failure recovery
15. observability

The numeric standards are fixed in `evaluator.ts`, including ≥98% authoritative onboarding capture, ≥95% high-value opportunity detection, zero contamination/leakage, 100% authoritative correction handling, and evidence requirements for important state/actions.

## Hard failures

The benchmark cannot average away:

- cross-workspace leakage
- founder/platform-test contamination
- unauthorized consequential execution
- fabricated external success
- authoritative correction ignored
- consequential current fact missing provenance
- stale superseded fact used as current
- silently skipped benchmark scenario
- required trace unevaluable

## Economic ledger

Each scenario records synthetic benchmark outcomes including owner minutes saved, customer wait avoided, revenue at risk/protected/created, interruption counts, autonomous completion, eligible work left undone, duplicate opportunities, and stale/wrong facts used.

## Running

```bash
npm run caye:employee:eval
```

This writes machine-readable JSON and a Markdown scorecard under `lib/caye-employee-eval/__output__/`.

To compare a candidate report generated by the exact same benchmark revision:

```bash
npm run caye:employee:eval -- --candidate=/path/to/candidate-report.json
```

A version mismatch makes the comparison non-comparable. New hard failures fail the candidate comparison test.

## Current-main baseline

`baseline-current-main.ts` is the frozen read-only observation captured against main revision `eda98a4547a20ed2c8ccd75d58fec662c1ceffeb`. It does not invent successful replay coverage that current main does not expose. ODS had onboarding data in `workspace_ai_config` but zero durable facts/candidates/opportunities. Bimini had durable memory, but the old pink-building pickup and newer Casino Tram Stop pickup were both unsuperseded current rows and relevant legacy facts lacked canonical keys.

That baseline is supposed to be uncomfortable. Its purpose is measurement, not morale.
